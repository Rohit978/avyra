# Plan 05-01: PostgreSQL GIN Trigram & Full-Text Search Indexes & Query Service

## Goal
Implement the database migration for `pg_trgm` extension and GIN indexes on primary and alternate titles, plus create the core search and discovery query service supporting both PostgreSQL ranking and SQLite unit testing fallback.

## Proposed Changes
1. **Alembic Migration**:
   - `backend/alembic/versions/0003_search_indexes.py`
   - Enable `pg_trgm` extension in PostgreSQL.
   - Create GIN trigram indexes on `media.title` and `media_titles.title`.
   - Create B-tree indexes on `media.release_date`, `media.popularity`, `media.vote_average`, `media.status`.
2. **Schemas**:
   - `backend/app/schemas/search.py`:
     - `MediaSummaryDTO`: ID, title, original_title, media_type, status, release_date, poster_path, backdrop_path, vote_average, vote_count, popularity, genres (names).
     - `SearchSuggestionDTO`: Lightweight summary for autocomplete (id, title, media_type, release_date, poster_path, vote_average).
     - `PaginatedResponse[T]`: Generic container for items, page, limit, total, total_pages.
3. **Search Service**:
   - `backend/app/services/search.py`:
     - `search_media(db, query, media_type=None, genre=None, year=None, page=1, limit=20)`: Multi-strategy match on canonical `Media` and alternate `MediaTitle` with dialect awareness (trigram similarity ranking for Postgres, ILIKE for SQLite).
     - `get_search_suggestions(db, query, limit=8)`: Lightweight fast query for autocomplete.

## Verification
- Unit tests in `backend/tests/test_search_service.py` asserting search queries match canonical titles, alternate titles, partial strings, and return proper pagination and suggestion limits.
